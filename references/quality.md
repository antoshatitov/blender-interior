# Проверка качества

## API helpers

`scripts/scene_checks.py` использует только Blender Python (`bpy`, `bmesh`, `mathutils`). Загружай через MCP по абсолютному пути:

```python
import importlib.util
spec = importlib.util.spec_from_file_location("interior_checks", SKILL_ROOT + "/scripts/scene_checks.py")
qa = importlib.util.module_from_spec(spec)
spec.loader.exec_module(qa)
result = qa.audit_scene()
```

Передавай пути обычными Python-строками, не вставляй их в shell-команды. Полные результаты пиши `qa.write_json(path,data)`, в MCP возвращай сводку.

До изменений сохрани `qa.snapshot(protected_names)`, после — `qa.compare_snapshot(baseline)`. Snapshot контролирует исходную геометрию/UV/атрибуты/shape keys/кривые, трансформации, parenting, модификаторы, ограничения, материалы и ноды, коллекции/видимость и ссылки. Дополнительно хешируется evaluated-геометрия: изменение внешнего Boolean-операнда обнаруживается даже при snapshot только защищённой стены. ID-ссылки не обходятся рекурсивно. Формат snapshot — 2; старые снимки несовместимы, новый baseline создавай до изменений.

Геттеры runtime RNA расширений не вызываются: они могут лениво создавать данные, например настройки Cycles. Уже сохранённые custom properties учитываются. Производные настройки расширений, не сохранённые в ID properties, проверяй отдельно. Evaluated-хеш включает координаты, рёбра, грани, их material index и smooth-флаги. Генерируемые модификаторами UV/прочие атрибуты требуют отдельной проверки; исходные UV/атрибуты входят в основной snapshot. Evaluated-контроль действует в текущем кадре и состоянии viewport; это не полный контроль анимации, симуляций, linked overrides, нереализованных instances или всех режимов Geometry Nodes. Содержимое внешних файлов и пиксели packed images не хешируются; если меняешь такие ресурсы, отдельно проверь их сохранность.

`qa.audit_scene(names=None,epsilon_m=1e-6)` проверяет evaluated mesh MESH/CURVE/FONT/SURFACE в метрах. Вырожденные грани — дефекты; открытые границы подтверждены как дефект только для ожидаемо замкнутой детали. Без роли — кандидат. Совпадающие вершины и инвертированный winding требуют оценки причины, особенно при отрицательном масштабе. Ткани/стекло/тонкие плоскости не обязаны быть замкнуты. Автоматического ремонта нет.

`qa.pair_candidates(names=None,max_pairs=2000)` выбирает пары по AABB; это не доказательство пересечения. У подозрительных пар вызывай `qa.inspect_pair(a,b)`: BVH evaluated-треугольников, проверка плоскостей и площади совпадения, кандидаты пересечений поверхностей. `ambiguous_contact_triangle_pairs` означает неразрешённые контакты: среди них возможны пересечения по рёбрам/швам. При ненулевом значении требуется дополнительный осмотр; ноль `crossing_surface_candidates` не доказывает допустимость контакта. Полное вложение одного тела в другое не исключается. При исчерпании лимита отмечай неполный охват, разбивай анализ по комнатам/узлам. Намеренные посадки не считаются дефектами.

## Соединения

Записывай установленные ожидаемые соединения в `assembly_contracts.json`:

```json
{
  "contacts": [{"a":"стойка","b":"дуга","max_gap_m":0.001,"reason":"соединение спинки"}],
  "motions": [{"root":"полотно","members":["ручка","розетка"],"axis":"Z","angle_degrees":45}],
  "intentional_pairs": [{"a":"крепление","b":"опора","reason":"посадка крепления"}]
}
```

`qa.check_contact(a,b,max_gap_m)` измеряет вершина–поверхность в обе стороны: верхнюю оценку минимального зазора. Для skew edge–edge контактов она может завысить зазор. Ответственное соединение проверяй с `anchor_a_world` — точкой узла на первом объекте в мировых единицах Blender. Контакт в другом месте не доказывает корректность данного соединения; подтверждай зазоры точкой и ракурсом. В старой модели сначала установи сборки, иначе отметь непроверенные соединения.

`qa.check_motion(root,members,axis="Z",angle_degrees=45)` проверяет фактический поворот корня и относительные трансформации деталей. `status` — `passed`, `failed` или `blocked`; `ok=True` только для `passed`. Если constraints блокируют поворот или задан нулевой угол, результат `blocked` означает невыполненную проверку, а не исправность сборки. Измеренный угол — `actual_rotation_radians`. Работает только на фоновой копии, восстанавливает transform в `finally`. Этот тест не доказывает свободное пространство: дополнительно проверяй пересечения на нескольких углах от закрытого до рабочего положения.

## Обход и ремонт

Пройди все этажи/комнаты/лестницу в SOLID; MATERIAL используй для нужных проверок материала/прозрачности. Осмотри уровень глаз, обратные стороны, верх/низ примыканий и небольшой поворот обзора у возможного z-fighting. Для обзора временно скрывай крышу/верхний этаж, сохраняя и восстанавливая настройки. Скриншотов viewport достаточно; рендеры не запускай. Без viewport визуальное QA незавершено.

Исправляй причину: конструкцию наложенных поверхностей, разрешённую деталь примыкания, крепление/родителя ручки, неправильную посадку. Сохраняй проёмы, проектные высоты и проходы. Не применяй массовое объединение вершин, заполнение всех отверстий или применение всех модификаторов. После трёх циклов без улучшения останови попытки данного узла.

Для каждого исправления фиксируй объект, причину, действие, измерение до/после и ракурсы. Перед сохранением сравни baseline. Сохрани полный snapshot результата и технические результаты в `checks.json`; повторно открой `result.blend` фоновым MCP, сравни snapshot, повтори проверки исправленных деталей и `qa.missing_files()`.

`report.md`: пути исходника/backup/результата, зоны и референсы, изменения, допущения, технический/визуальный охват, проблемы вне области ремонта и оставшиеся ограничения. Итог — ссылка на `.blend` и короткий статус. Пустой список non-manifold не означает «ошибок нет».

## Проверка самого skill

После изменения helpers загрузи `scripts/self_test.py` через `importlib.util` в отдельном фоновом процессе MCP Blender и вызови `run(absolute_test_directory)`. Скрипт сбрасывает сцену и создаёт тестовые детали: никогда не запускай его в рабочей интерактивной модели. Затем повторно открой созданный `fixtures.blend` фоновым MCP и сравни `snapshot_before_save.json` через `qa.compare_snapshot`. Визуальный обход и перенос полного интерьера проверяй отдельно на копии реального проекта.
